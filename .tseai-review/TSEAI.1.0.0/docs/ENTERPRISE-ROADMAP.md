# TSEAI Enterprise Hardening Roadmap

This roadmap uses evidence-based release readiness. A sprint is complete only when its automated source acceptance criteria pass from a clean checkout; production claims additionally require fresh evidence from the target environment.

## Sprint 41 — build integrity and deterministic correctness

Status: **COMPLETE**

- Entire .NET solution restores in locked mode and builds with warnings treated as errors.
- Every console smoke project is discovered and executed automatically.
- Python tests and module compilation pass.
- Temporal, filter, comparison and migration defects found by the build are fixed.
- NuGet and npm dependency graphs are committed as lock files.

## Sprint 42 — evaluation and release-gate integrity

Status: **COMPLETE; live execution remains a Sprint 45 gate**

- Golden evaluation covers all 320 cases without disabling product quota/rate limits.
- Reports carry version, timestamp and Golden Dataset SHA-256 provenance.
- Missing validation fields fail closed.
- GA requires matching version/dataset and fresh live production evidence.
- Production acceptance is generated by automation, never inferred from file existence.

## Sprint 43 — reproducible supply chain

Status: **SOURCE COMPLETE; registry signing requires the selected deployment platform**

- `npm ci`, production build and vulnerability audit pass.
- NuGet locked restore and dependency audit pass.
- Python dependencies install from a hash-verified lock and pass vulnerability audit.
- CycloneDX SBOM is generated and version-matched.
- Final registry image scan, immutable digest promotion and signed provenance remain deployment-CI responsibilities.

## Sprint 44 — security, tenancy and operational resilience

Status: **SOURCE CONTROLS COMPLETE; target-environment integration tests remain open**

- Refresh-token families, transactional rotation, replay revocation and secure browser cookie flow are implemented.
- Authorization/ownership boundaries, OTP/refresh limits and safe error handling are enforced.
- SSRF, prompt/tool injection, SQL safety and MCP allowlists have static and DAST gate coverage.
- Correlation IDs, structured audit/incident records, real operations counters and dependency-aware readiness are implemented.
- HTTP calls and service health probes are bounded; hardened containers are non-root/read-only where applicable.
- Live negative auth, tenancy, broker/database and observability backend integration remain Sprint 45 evidence.

## Sprint 45 — production certification

Status: **BLOCKED on target platform, production secrets, authoritative data and SLO decisions**

- Pass real SQL AI, Redis, RabbitMQ and Qdrant integration checks.
- Perform destructive restore into isolated targets and verify data integrity.
- Meet approved load, stress and soak SLOs.
- Exercise rolling deployment, rollback and disaster-recovery runbooks.
- Produce fresh live Golden, DAST and E2E evidence leading to `GA_READY`.

## Decisions required before final production certification

1. Target platform: on-premise Kubernetes, a specific cloud, or Docker Compose only.
2. Required Iranian/regulatory baseline: internal policy, IFTA, ISO 27001, SOC 2, or a combination.
3. Approved LLM/embedding providers, data-residency boundary and retention policy.
4. Production SLOs: availability, p95/p99 latency, RPO/RTO and peak concurrent users.
5. Authoritative SQL AI schemas and a non-production masked integration dataset.
